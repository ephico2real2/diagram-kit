## C1: the example tests passed when their rules were broken

**Finding (LightSaber).** An empty `role="status"` and 20 px touch targets kept `tests/test_mockup_example.py`
green. A leftover `{{` in a comment was never seen, because the check read only the visible text. The fix: test the
words of each live region, measure each control, and add a status to the summary's loading state.

**Re-check.** The same mutations, run here on a copy, kept the old suite green. After the fix, the empty list status
fails 1 test, 20 px targets fail 14, and a `{{` comment inside `#app` fails 42.

**Decision.** Accepted. `242d5ee` tests the words of six live regions in two sections and the 44 px minimum of each
visible control in each view and role at 390 px. The leftover check also reads the markup of `#app`. A comment
outside `#app` is not tested, because the header comment of the example names `{{c.<token>}}` on purpose.

## C2: the example broke rules of the build skill

**Finding (LightSaber).** The summary's loading state had no status line. Its error had no "Try again".
"Create workspace" did nothing. The `deleting` state key was declared and never used. The skill said that the
example "obeys every rule", but a plain HTML file cannot have the shape of section 1 or the `{{c.}}` markup of
section 2.

**Re-check.** At `eb2119f`, `?view=loading` has 0 status lines in the summary, and a click on "Create workspace"
leaves `data-state="empty"`.

**Decision.** Accepted. Each gap is fixed in `242d5ee`, and each has a test: on the old example, 5 of the new tests
fail. A new test checks that the state object holds each declared key and no other. The skill and the example header
now say that the example obeys sections 0 and 2 to 8, and which two canvas rules do not apply.

## C3: Query's retries keep the section in loading

**Finding (LightSaber).** Both TSX blocks compile with `tsc --strict`, and `isAriaDisabled` blocks the click. But
`useWorkspaces` keeps TanStack Query's default retries, so a network fault shows `loading` for about 7 s.

**Re-check.** With `@tanstack/query-core` 5.106.0 in browser mode, the defaults make 4 calls and give `isError`
after 7,008 ms. With `retry: false`, 1 call and 0 ms. The snippets, taken from the skill files, compile with
TypeScript 7.0.2 for React, PatternFly and Preact (exit 0).

**Decision.** Accepted. `149b902` sets `retry: false`, and the prose says why. A test checks the hook.

## C4: 401, 404, 422 and 429 all became `error`

**Finding (LightSaber).** The fetch maps only 403. The proposed fix adds four states: `unauthorized`, `notFound`,
`invalid` and `rateLimited`.

**Re-check.** Correct for the code at `eb2119f`.

**Decision.** Accepted on the fact, snippet rejected. The six states are a closed list that the three skills, the
example and the tests share. Four more states would change the standard for each mockup. `/mockup-to-page`
section 4 now says what each answer becomes: the app shell handles 401, a 404 to a read of one object is `empty`, a 422
shows field errors, and a 429 is `error` with a retry after `Retry-After`. If a mockup needs words for one of these,
its owner adds them. A test checks all four rules.

## C5: the page skill did not name `react-pf-ts`

**Finding (LightSaber).** Mostly consistent. `/mockup-to-page` never names the third target, and the skill
overclaims (see C2).

**Decision.** Accepted. `/mockup-to-page` sends a `react-pf-ts` mockup to `/mockup-to-page-react`. Tests check that,
and that the README names the three targets and the number of section types.

## C6: the PatternFly skill did not repeat the secret and permission rules

**Finding (LightSaber).** Escaping holds against an injected name. The `role` preview prop computes permissions in
the browser. That is acceptable only in a mockup. `/mockup-to-page-react` does not repeat the ban on secrets.

**Decision.** Accepted. The example marks that code as the sample answer of the API. The build skill says that the
page never calculates permissions from a role. `/mockup-to-page-react` section 5 repeats both rules. A test checks
that each of the three skills states both rules.

## C7: an owner of a PatternFly token screen had to invent parts

**Finding (LightSaber).** Five gaps: content parity versus the look, the one-time token, 401, a delete with confirm
and conflict, and retries.

**Decision.** Accepted in part. The one-time token is a mapping row (`Alert` with the focus, `ClipboardCopy`, never in
a query key, the URL or a fixture). 401 is covered by C4 and retries by C3. A full `useMutation` example for delete
with conflict is rejected here, because the plan asks for a small example. It goes to OBI-45 as a question for the
portal. Content parity is in section 6 of the skill.

## C8: a host font could make the 390 px check flake

**Finding (LightSaber).** The example uses `system-ui`. The proposed fix pins a font.

**Re-check.** With monospace, serif, Courier New and Verdana forced on each element, the page does not scroll
sideways at 390 or 820 px.

**Decision.** Accepted on the fact, snippet rejected. No font is pinned, because the layout fits wide fonts. A test
forces the four fonts and guards it.
